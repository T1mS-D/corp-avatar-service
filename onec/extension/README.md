# Расширение 1С:УНФ — интеграция с сервисом генерации аватаров

Полноценный `.cfe`-файл нельзя собрать вне платформы 1С:Предприятие, поэтому здесь —
**исходный код на BSL**, который добавляется в расширение через Конфигуратор.
Это стандартная практика хранения конфигураций 1С в git (аналог `.cf`/`.cfe` в текстовом виде).

## Вариант А (текущий): без хранения фото в 1С

Фото сотрудника **не хранится в базе 1С вообще**. При нажатии кнопки пользователь выбирает
файл прямо с диска (стандартный диалог платформы), сервис получает его вместе с
идентификатором сотрудника, и возвращает результат — тот показывается на форме и по желанию
сохраняется на диск. Структура справочника «Сотрудники» при этом не меняется ни на один
реквизит — используется только системный идентификатор ссылки, который есть у любого элемента
любого справочника «из коробки» (подробнее — раздел «Как это работает» ниже).

Это осознанный выбор для демо/учебной базы, где нет реквизита для хранения фото. Если позже
понадобится хранить фото/аватары внутри самой базы 1С — это отдельная доработка («Вариант Б»),
для которой в `src/ПримерХраненияФайлов.bsl` есть отправная точка.

## Состав

| Файл | Куда вставить в Конфигураторе |
|---|---|
| `src/ИнтеграцияГенерацияАватаров.bsl` | Новый общий модуль расширения (см. настройки ниже) |
| `src/ФормаСотрудникаРасширение.bsl` | Модуль расширяемой формы `Справочник.Сотрудники.ФормаЭлемента` |
| `src/ТестПодключения.bsl` | Не часть расширения — отдельный скрипт для проверки сети до того, как всё остальное собрано |
| `src/ПримерХраненияФайлов.bsl` | Опционально, только для «Варианта Б» (см. выше) — сейчас не нужен |

## Шаг за шагом (10–15 минут)

1. **Конфигуратор → Конфигурация → Расширения → Добавить.**
   Имя: `ГенерацияАватаров`, назначение — «Дополнение».
2. **Общие модули → Добавить.** Имя `ИнтеграцияГенерацияАватаров`.
   Свойства модуля: `Сервер = Истина`, `Клиент (управляемое приложение) = Ложь`,
   `Внешнее соединение = Истина`, `Повторное использование = Не использовать`.
   Вставьте содержимое `src/ИнтеграцияГенерацияАватаров.bsl` целиком, без изменений.
3. **Константы** (Общие → Константы → Добавить, тип Строка, длина не ограничена):
   - `АватарыURLСервиса` — например, `http://localhost:8000` (учебная база и Docker на одной
     машине) или `http://<IP-адрес>:8000` (если на разных); порт — из `.env` → `API_PORT`;
   - `АватарыAPIKey` — значение переменной `API_KEY` из `.env` сервиса.
   Задайте значения через форму констант в режиме 1С:Предприятие (проще всего) или в Конфигураторе.
4. **Права доступа** (для боевой базы с кластером серверов): разрешите использование
   интернет-ресурсов для рабочего сервера 1С, если список разрешённых адресов ограничен.
   Для учебной файловой базы этот пункт обычно не нужен.
5. **Форма сотрудника**:
   - расширяемый объект `Справочник.Сотрудники`, расширяемая форма `ФормаЭлемента`;
   - три команды на командной панели формы: `ВыбратьФотоСДиска` («Выбрать фото с диска»),
     `СоздатьАватар` («Создать аватар»), `СохранитьАватарКакФайл` («Сохранить как файл»);
   - **новый реквизит ФОРМЫ** (не справочника!) `АдресРезультатаАватара`, тип **Строка**
     (добавляется в дереве самой расширяемой формы — справочник это не затрагивает);
   - элемент формы «Поле картинки», свойство «Путь к данным» = `АдресРезультатаАватара`
     (чтобы результат сразу показывался на форме);
   - вставьте код формы из `src/ФормаСотрудникаРасширение.bsl`.
6. Сохраните и подключите расширение к базе — готово.

## Если у вас учебная/демонстрационная база УНФ (не боевая)

- Пункт 4 (файрвол кластера серверов) обычно можно пропустить — учебная база чаще всего
  файловая; если 1С и Docker Desktop (WSL2) — на одной машине, `http://localhost:8000`
  должен быть доступен сразу.
- Перед сборкой формы стоит сначала проверить саму сеть, не трогая расширение:
  `src/ТестПодключения.bsl` — самодостаточный скрипт для любой «консоли кода» (внешняя
  обработка для выполнения произвольного BSL) или временной серверной кнопки. Ожидаемо
  увидите код ответа `200`.

## Как это работает

Три шага пользователя: **«Выбрать фото с диска»** → **«Создать аватар»** → (когда готово)
результат виден прямо на форме, опционально — **«Сохранить как файл»**.

Технически, платформа 1С не разрешает блокирующее ожидание на сервере (нет способа сделать
`sleep` в серверном коде — это заняло бы рабочий процесс сервера на всё время ожидания и
мешало бы другим пользователям), поэтому обмен с сервисом устроен в два слоя:

- **Общий модуль** (`ИнтеграцияГенерацияАватаров`) — три коротких серверных функции
  (`ОтправитьФотоНаГенерацию`, `ПолучитьСтатусЗадания`, `ПолучитьИзображениеАватара`), каждая
  делает ровно один быстрый HTTP-вызов и сразу возвращает управление. Есть и блокирующая
  `СгенерироватьАватарИДождаться` — она ограничена условием компиляции только контекстом
  «Внешнее соединение» (для внешних COM/OLE-скриптов на Python/.NET/PowerShell), вызывать
  её с сервера (из формы) нельзя — она сама кинет понятное исключение.
- **Форма сотрудника** (`ФормаСотрудникаРасширение.bsl`) — фото читается платформой во
  временное хранилище (`НачатьПомещениеФайла`), передаётся на сервер
  (`ПолучитьИзВременногоХранилища`), клиент раз в 3 секунды опрашивает статус через
  `ПодключитьОбработчикОжидания`, готовый результат снова кладётся во временное хранилище
  (`ПоместитьВоВременноеХранилище`) и показывается через привязку картинки к адресу,
  скачивается — через `НачатьПолучениеФайла`.

Идентификатор сотрудника (`employee_ref`) — это `Ссылка.УникальныйИдентификатор()`, системное
свойство, которое есть у любого элемента любого справочника 1С «из коробки», без каких-либо
изменений в структуре данных. Сопоставление «фото ↔ сотрудник» происходит на стороне сервиса:
1С передаёт этот идентификатор вместе с фото в одном HTTP-запросе, а сервис сохраняет связку
в таблице `avatar_jobs` (колонка `employee_ref`) в PostgreSQL.

Все обращения идут через стандартные объекты платформы `HTTPСоединение`/`HTTPЗапрос`
и `ЗаписьJSON`/`ЧтениеJSON` — внешние компоненты и библиотеки не требуются.

## Проверка без реальной базы 1С

Быстро проверить сам сервис можно `curl`-ом (см. корневой `README.md`, раздел «Быстрый старт»)
или через Swagger `/docs` — 1С обращается к тем же самым эндпоинтам.
