# Архитектура

```
                         ┌────────────────────────┐
  1С:УНФ (расширение) ──▶│   FastAPI  (app/api)   │──▶ PostgreSQL (avatar_jobs)
  HTTP + X-API-Key        │  POST /avatars (base64)│         ▲
                          │  GET  /avatars/{id}    │         │ SELECT...FOR UPDATE
                          │  GET  /avatars/{id}/img│         │ SKIP LOCKED
                          └────────────┬───────────┘         │
                                       │ файл на /data        │
                                       ▼                      │
                          ┌────────────────────────┐          │
                          │   /data (общий том)    │          │
                          └────────────┬───────────┘          │
                                       │                      │
                          ┌────────────▼───────────┐          │
                          │  worker (app/worker.py)│──────────┘
                          │  poll loop, 1 задание   │
                          │  за раз на воркер       │
                          └────────────┬───────────┘
                                       │
                     ┌─────────────────┴──────────────────┐
                     ▼                                     ▼
        PIPELINE_BACKEND=classic                PIPELINE_BACKEND=diffusion
   (CPU, без генеративных моделей)         (GPU, Stable Diffusion inpainting +
   rembg (u2net) — маска человека           IP-Adapter FaceID + img2img для
   + композит с готовым фоном               мульт-стиля)
                     │                                     │
                     └─────────────────┬──────────────────┘
                                       ▼
                     InsightFace (buffalo_l, ArcFace) — везде:
                     детекция лица, поза, эмбеддинг для проверки схожести
```

## Почему так

- **Очередь в самой БД** (`SELECT ... FOR UPDATE SKIP LOCKED`), а не Redis/RabbitMQ — на 5-дневный
  спринт это на порядок быстрее поднять и отладить, при этом даёт настоящую атомарность и
  устойчивость к падению воркера (см. `requeue_stuck`). Для роста нагрузки замена на Celery/RQ
  делается локально — воркер уже выделен в отдельный процесс, а не встроен в API.
- **Два бэкенда пайплайна за одним интерфейсом** (`AvatarPipeline`): `classic` — CPU, работает
  без GPU и генеративных моделей (кадрирование + сегментация + замена фона), нужен как
  быстрый демо/фолбэк и для тестов без GPU. `diffusion` — полноценная замена одежды и
  мульт-стиль, требует NVIDIA GPU. Выбор — одна переменная окружения `PIPELINE_BACKEND`.
- **Открытые модели**: InsightFace `buffalo_l` (детекция/эмбеддинги лица, MIT-подобная
  лицензия проекта, веса — non-commercial research, см. `docs/models.md`), rembg/u2net
  (сегментация человека), Stable Diffusion 1.5 inpainting + IP-Adapter FaceID (замена одежды
  с сохранением лица), SD img2img (мульт-стиль). Всё скачивается автоматически при первом
  запуске и кэшируется в `/models`.
- **Сохранение лица — не одна проверка, а три независимых механизма**, подробно описанные
  в docstring `app/pipeline/diffusion.py`: (1) физическая неприкосновенность пикселей головы
  вне маски inpaint, (2) IP-Adapter FaceID прямо в процессе генерации, (3) пороговая проверка
  ArcFace-сходства с ретраями и понижением интенсивности по мере попыток.
- **PostgreSQL, а не файлы/SQLite** — по прямому требованию проекта (см. `Доп. требования`),
  плюс это даёт истории заданий, статистике и будущей аналитике в 1С готовую СУБД.

## Формат сервиса

Синхронный HTTP-запрос из 1С не должен зависать на 10–30 секунд генерации, поэтому API асинхронный:
`POST` сразу возвращает `202 Accepted` и `job_id`, а результат забирается опросом
(`GET /avatars/{id}`) или ожиданием на стороне 1С (см. `onec/extension`, функция
`СгенерироватьАватарИДождаться`, которая просто оборачивает эту же схему в цикл).
